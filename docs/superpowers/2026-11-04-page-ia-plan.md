## 2. 第一階段：類型入口（核准後先做）

### 2.1 探索首頁
- 順序改為：搜尋 → 本季新番 → **依類型探索** → 本週熱門。類型是滑卡功能的入口，不該排在最底下。

### 2.2 新頁：類型頁 `(rate)/genre/[id]`
點類型方塊後先進這頁，不直接進卡堆。
- `ScreenHeader`：類型名稱，副標「依 AniList 人氣排序」。
- 頂部封面（第一幀直接用 route param 傳來的 `image`，高度約 160，圓角 8）。
- 唯一的大 CTA（`ThemedButton size="lg"`）：「開始滑卡」。若這類型的卡堆還在記憶體快取且有進度，改成「繼續滑卡（已滑 N 張）」，數字來自 deck cache 的 `currentIndex`。旁邊附一行說明：右滑加入「想看」、左滑略過（依目前模式顯示）。
- 「這類型最熱門」：用跟卡堆同一份第一頁資料（`loadGenreSwipePage(id, 1)`），列出前 20 部，沿用 `TrendingRow`（名次、封面、分數、集數）。點了進作品詳情。
- 首幀不 await：新增 `AnimeRepository.getAnimeByGenreSync`（讀 `CacheService.getSync`）。快取有資料就直接畫；沒有就顯示 `Skeleton.ListRow`；失敗顯示「無法載入＋重試」。
- 這頁與卡堆共用同一個 in-flight／快取，所以先看列表再按 CTA，卡堆可以立刻開。

### 2.3 卡堆 `(rate)/rating`

- 寫死的顏色改用主題；空狀態與看完狀態改用 `ThemedText` + `ThemedButton`。看完時的主按鈕是「回到 {類型}」，次要按鈕是「重新開始」。
- 滑卡邏輯、廣告插入、持久化**一律不動**（廣告剛改完）。

## 3. 第二階段：分數與方塊（卡片）顯示規則

稽核發現：同一個 AniList `averageScore`（0–100）在不同地方長得不一樣。滑卡顯示 `★ 83`，首頁與趨勢顯示 `★ 8.3`，播出表的卡堆顯示原始值 `83`。作品詳情沒有分數時顯示 `★ N/A`。另外有三份各自寫的 `formatScore`。

規則（一次定案）：
- **社群分數**一律是 0–10、一位小數、前面加 ★，全部走 `libs/utils/format-score.ts`。沒有分數或分數 ≤ 0 時**整個隱藏**，不顯示 N/A 或 0。
- **我的分數**（收藏裡自己打的分數）只出現在收藏與進度編輯，標示「我的評分」，不和社群分數混在同一個位置。
- 分數顯示的位置：探索類（首頁列表、類型頁、滑卡、趨勢、搜尋、作品詳情）顯示社群分數。播出表**不顯示**分數，那頁的重點是時間。
- 滑卡卡片底部只放：標題、年份 · 類型、分數。「點看詳情」提示只在每次進入卡堆的第一張出現，之後隱藏（點卡片看詳情屬於隱性操作）。

## 4. 第三階段：追番 ↔ 設定

稽核發現：「集數提醒」有兩個開關，各存一份。播出表設定面板存在 `bangumiPrefs.notificationsEnabled`，設定 → 通知存在 `notificationPrefs.episodeReminders`。只關掉其中一個時，按鈴鐺會加進想看，但不會排提醒，也沒有任何說明。播出表面板裡的「顯示成人內容」其實是全 App 共用的開關，說明卻寫成「只影響季番」。

規則：
- 集數提醒只有一個真實來源：`notificationPrefs.episodeReminders`。播出表面板的開關直接讀寫它，另外加「提醒時間與通知設定 →」連到 `/setting/notifications`。`notificationsEnabled` 欄位保留在型別裡，只讓舊的存檔能讀，不再使用。
- 成人內容開關移出播出表面板，改成一列「內容與資料來源 →」連到設定（真正的開關只在設定頁）。
- 播出表的列：兩行 meta 合併成一行「第 5 集 · 今天 21:26」。日期只在不是今天或明天時才寫出來。
